# Migration plan: option B (Vercel + Neon, no Supabase)

Status: **proposed**, not started (2026-11-08). The user chose B. Background: `research-ux-hosting.md` Parts 3 and 6.

## Target
| Piece | Now | After |
|---|---|---|
| App hosting | Vercel Hobby | Vercel Hobby (unchanged), functions in Frankfurt (`fra1`) |
| Database | Supabase Postgres (pauses after ~7 idle days) | **Neon** Postgres, AWS Frankfurt (wakes automatically) |
| Login | Supabase Auth (email sign-up + confirmation email) | **Better Auth** in our app: email + password, sessions in our DB, no public sign-up |
| File storage | Supabase Storage (written, never read) | **none** |
| Backups | none | nightly `pg_dump` → GitHub Actions artifact (90 days) |
| Data migration | — | none: there is no production data to keep |

## Phase 1: code (Claude, ~1 session, on a branch, tested locally)
1. **Login:** add `better-auth` with its Prisma adapter. Schema: `User` gains Better Auth's fields; new `Session`, `Account`, `Verification` tables. `Project`/`Chart` are unchanged. `getUser()` in `lib/auth.js` keeps its `{ id, email }` shape, so the API routes don't change. `proxy.js` checks the session cookie; pages and API routes do the real check. The dev bypass stays as is.
2. **Pages:** a new `/login` (email + password); delete `/signup`, `/auth/callback`, `/api/users/sync`; sign-out in `Header`.
3. **Accounts:** an `/admin` page for the emails in `ADMIN_EMAILS`: add a user (email + temporary password), reset a password, remove a user. First run: an admin email with no account yet sets its password on the login page.
4. **Storage:** delete `/api/upload` and the upload call in the editor. Leave `Chart.dataFileUrl` unused (no schema churn).
5. **Clean-up:** remove `@supabase/*` and `lib/supabase/`; update `.env.example`, `CLAUDE.md` (stack line), and the `frontend-ui` skill note about `getUser`.
6. **Database setup file:** `docs/neon-schema.sql`, generated by `prisma migrate diff` (empty → schema), for pasting into Neon's SQL editor once.
7. **Backups:** `.github/workflows/backup.yml`, nightly plus a manual "run now" button: `pg_dump` from Neon → artifact.
8. **Tests:** unit and e2e as now (dev bypass), plus an e2e run with the bypass **off**: login, wrong password, admin adds a user, a non-admin can't open `/admin`, signed-out pages redirect.

## Phase 2: accounts and settings (the user, ~30 min, best on a PC)
A step-by-step runbook with screenshots-in-words goes into `docs/runbook-neon-vercel.md` during Phase 1.
1. **Neon:** sign up (GitHub login works). Create project `laser-charts`, region **AWS Europe Central (Frankfurt)**. Copy the **pooled** and **direct** connection strings.
2. **Tables:** Neon → SQL editor → paste `docs/neon-schema.sql` → Run.
3. **Preview database (recommended):** in Neon, create a branch `preview` (copy of main, free). Branch previews then never touch real data.
4. **Vercel → Settings → Environment Variables:**
   - Production: `DATABASE_URL` (pooled), `DIRECT_URL` (direct), `BETTER_AUTH_SECRET` (random; the runbook says how), `BETTER_AUTH_URL` (the site address), `ADMIN_EMAILS`.
   - Preview: the same, but the `preview` branch's connection strings.
   - Delete `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
   - Settings → Functions → region **Frankfurt (fra1)**.
5. **GitHub → Settings → Secrets → Actions:** `BACKUP_DATABASE_URL` (Neon direct string) for the nightly backup.
6. **Go live:** merge the branch into `main` → Vercel deploys. Open the site, set the admin password, create the researchers' accounts in `/admin`, send them their passwords.
7. **Check, then clean up:** run the backup once ("Run workflow"), and confirm the artifact appears. Then delete the Supabase project.

## Risks
- Better Auth + Next 16 `proxy.js`: if the cookie helper misbehaves, protect pages inside the pages instead (small fallback).
- Neon free: ~1 s wake-up after 5 idle minutes; a 6-hour restore window (covered by the nightly backup).
- Free plans can change their terms. Moving to C2 later is a `pg_dump`/restore plus env changes.
- No email = no self-service "forgot password". An admin resets it.
